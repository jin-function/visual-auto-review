# 앱 3.5.0 · 확장 1.4.0 리팩토링

## 반영한 항목

| 항목 | 구현 |
| --- | --- |
| PC·MO 통합 전달 | `qa/chrome_review.py`가 실행 단위 v3 묶음을 생성하고 대상별 비교 버전을 고정합니다. |
| 한 번 불러오기 | `core.mjs`의 전체 검증 후 `db.js`의 단일 트랜잭션으로 묶음·대상·이미지를 등록합니다. |

| 실제 표시 상태 | `content.js`는 그림 그리기가 끝난 뒤 표시 상태를 알립니다. 누락·숨김·불러오기·화면 범위 밖을 구분합니다. |

| 공통 검수 화면 | `view.mjs`, `toolbar.js`, `client.mjs`를 사이드패널과 개발자도구에서 함께 사용합니다. |
| 앱 책임 분리 | `Projects`, `Jobs`, `Revisions`가 프로젝트 검증·작업 수명·결과 생성을 담당합니다. |
| 응답 순서와 상태 갱신 | 앱은 선택 세대가 바뀐 응답을 무시하고, 확장은 상태 변경 알림으로 화면과 다른 창의 파일 정보를 갱신합니다. |
| 좌표 경계 | `qa/coordinates.py`, `overlay-layout.js`에서 시안·문서·캔버스의 좌표 변환을 관리합니다. |
| 검수 판단 전달 | 상태·심각도·메모를 파일에 포함하고 확장에서 필터링합니다. 내보내기에는 묶음·대상·버전 출처를 기록합니다. |
| 수정본 저장 분리 | 브라우저 수집은 `export-collector.mjs`, 정리는 `sanitize.mjs`, 원본 CSS 병합과 파일 생성은 기존 모듈로 분리합니다. |
| 메모리와 목록 조회 | 이미지 바이트를 메타데이터와 분리하고 압축 이미지 캐시를 제한합니다. 앱은 결과 요약을 캐시하고 비교 텍스트 마스크를 타일로 처리합니다. |
| 이동한 차이 후보 | `review_history.py`가 같은 요소의 이동 후보를 제공합니다. 증거가 다른 이전 승인을 자동 승계하지 않습니다. |
| 검증·배포 | 규격 예제, 실제 앱 HTTP 파일→확장, 앱 UI 다운로드, 저장 구조 변환 검사를 추가하고 운영체제별 CI를 구성합니다. |

## 유지한 동작

기존 검수 결과 화면, 단일 비교 엔진, 전체 영역 비교, 보정 전후 버전 보존을 유지합니다.
`app/page_state.js`와 아코디언 동작을 변경하지 않았습니다.
원본 파일명, CSS 서식 보존, 검수용 마크업 제거 검사를 유지합니다.
HTML은 현재 DOM 사본을 내보내므로 원본 HTML의 들여쓰기까지 복원하는 기능은 포함하지 않습니다.

## 데이터와 업데이트

앱은 기존 `VisualQA/v3` 데이터 폴더를 사용합니다.
확장 데이터베이스는 v1에서 v2로 변환하며 이전 원본 포함 개별 파일을 지원합니다.
통합 파일은 두 시안 중 일부가 없을 때도 누락 상태를 명시합니다.

앱을 다시 실행하고 확장을 새로고침한 뒤 새 통합 JSON을 불러옵니다.
기존 개발자도구 수정 내용은 확장 새로고침 전에 저장합니다.
설치본 갱신 전 기존 앱과 확장 폴더를 백업합니다.

## 검증 범위

- Python 단위 검사 47개.
- JavaScript 단위 검사 16개.
- Chrome 실제 통합 흐름 69개: 기존 검사와 v3 묶음·이전 데이터 변환·앱 UI 검사를 함께 실행합니다.
- 실제 앱 실행, 캡처, 보정 재계산, 판단 기록, 보고서 저장.
- 실제 HTTP 다운로드의 원본 이미지와 접근 제한.
- 원본 CSS의 CRLF·들여쓰기·주석·파일명과 검수 도구 제거.
- macOS 앱 빌드·서명 검증과 소스 파일 일치 확인.

로컬 브라우저 검증 환경은 macOS Intel, Node 22.21.0, Python 3.12이며 Chrome for Testing 149.0.7827.55와 156.0.8078.80에서 전체 흐름을 통과했습니다.
GitHub Actions에는 Windows·macOS·Linux 단위 검사와 Linux 가상 화면의 Chrome 검사를 구성했습니다.
화면 없는 Mac의 최신 Chrome에서 시작·탐색이 간헐적으로 멈추는 현상을 확인하여 원격 확장 검사는 가상 화면에서 실행합니다.
Windows에서의 실제 Chrome 조작은 로컬 검증 범위에 포함하지 않았습니다.
