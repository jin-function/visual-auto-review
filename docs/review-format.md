# 검수 묶음 v3

앱 3.5.0과 확장 1.4.0이 사용하는 오프라인 전달 규격입니다.
앱의 인증 토큰과 소스 폴더 경로를 포함하지 않습니다.
원본 이미지는 PNG 바이트의 base64이며 이미지마다 SHA-256을 검증합니다.

`app/review-contract.json`이 규격 버전과 제한값의 기준입니다.
`tools/sync_contract.py`가 확장 상수와 JSON Schema를 생성하며 CI에서 일치 여부를 검사합니다.
Schema 외에 같은 실행·페이지 여부, 대상 중복, PNG 크기·픽셀 수·SHA 검증을 생산자와 소비자 검사로 보완합니다.

| 필드 | 의미 |
| --- | --- |
| `format`, `version` | `visualqa.chrome-review`, `3` |
| `packageId` | 실행·반응형 설정·선택한 대상 버전·이미지 해시로 만든 식별자 |
| `runId`, `name`, `url` | 검수 실행과 실제 페이지 |
| `producer.appVersion` | 내보낸 앱 버전 |
| `responsive.breakpoint` | PC를 표시하기 시작하는 CSS 뷰포트 폭 |
| `captureOptions.removeHidden` | 검수 실행 당시의 `hidden` 속성 제거 여부. 이전 파일에서는 생략 가능 |
| `coordinateSpace` | `reference-display-css-pixels-v1` |
| `targets` | 완료된 PC·MO 결과, 장치별 최대 하나 |
| `unavailable` | 결과가 없는 장치와 사유 |

각 대상에는 명시적인 `device`, `targetId`, `revisionId`, 원본 `image`, `display`, `viewportWidth`, `placement`, `findings`를 저장합니다.
차이 항목에는 검수 판단과 메모의 내보내기 시점 사본을 포함합니다.
대상은 같은 실행·페이지에 속해야 합니다.
한 대상이 실패했거나 검수하지 않았다면 부분 묶음을 허용하고 해당 장치에서는 누락 상태를 표시합니다.

프로젝트에 추가 검수 폭이 있다면 PC·MO 오버레이 대상으로 사용할 항목을 프로젝트 설정에서 정합니다.
현재 화면에서 선택한 비교 버전은 해당 대상에 적용하고, 다른 대상은 최신 완료 버전을 사용합니다.
파일 생성은 저장소 잠금 안에서 버전 선택을 고정한 뒤 수행합니다.

`captureOptions.removeHidden`은 현재 프로젝트 설정이 아니라 해당 검수 실행에 저장된 설정입니다.
확장에서 파일을 불러오면 이 값으로 미리보기 옵션을 설정합니다.
이 필드가 없는 이전 파일은 확장에 저장된 옵션을 유지합니다.

## 좌표

`image.width/height`는 원본 PNG 픽셀 크기입니다.
`display.width/height`는 비교에 사용한 CSS 표시 크기입니다.
원본 PNG가 표시 폭과 달라도 원본 바이트를 유지합니다.

`findings.rect`는 표시 크기로 조정한 시안의 좌상단 기준입니다.
`placement`는 그 시안을 실제 문서에 놓을 CSS 좌표이며 캡처 범위와 Y 보정을 포함합니다.
확장의 추가 이동·배율은 그 위에 적용합니다.

앱의 좌표 변환은 `qa/coordinates.py`, 확장의 화면·캔버스 변환은 `overlay-layout.js`에서 관리합니다.
캔버스 최소 폭과 중앙 정렬은 실제 페이지 레이아웃을 수정하지 않습니다.

## 저장과 호환

확장은 묶음 정보, 대상 정보, 이미지 바이트를 분리해 저장합니다.
모든 대상 검증을 끝낸 뒤 하나의 IndexedDB 트랜잭션으로 등록합니다.
일부 이미지가 손상되면 새 묶음을 저장하지 않습니다.

기존 개별 시안 데이터베이스 레코드는 이미지 저장 분리와 묶음 정보 생성으로 변환합니다.
v2 개별 JSON은 같은 실행·페이지 단위로 묶고, v1 차이 강조본은 다시 내보내도록 안내합니다.
지원 범위보다 새로운 규격은 확장 업데이트를 안내합니다.

묶음별 사용자 설정은 영구 저장소, 탭 연결은 세션 저장소에 둡니다.
검수 묶음을 바꾸면 이전 이미지 캐시를 비웁니다.
문서의 압축 이미지 캐시는 32MB, 확장 이미지 읽기 캐시는 96MB로 제한합니다.
비트맵은 현재 시안 하나만 유지합니다.
